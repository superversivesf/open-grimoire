# Open Grimoire — Multi-Agent Deep-Dive Audit (2026-08-16)

Three independent agents (pi/kimi-k2.6, codex/qwen3.5, claude/minimax-m3) audited
the codebase with distinct focus angles, then cross-verified each other's findings
in a second round. Verdicts below reflect the round-2 consensus.

## Consensus: CONFIRMED bugs (all 3 agents agree)

### HIGH — Security

**1. Stale admin privileges — demoted admins keep admin until cookie expiry (24h)**
- `app/auth/middleware.py:43-58` — `verify_session` returns `is_admin` from the signed
  token payload; the DB lookup only runs `if uid and not is_admin`. A demoted admin's
  existing cookie keeps asserting admin for the full 24h TTL.
- Fix: always verify `is_admin` from the DB (or invalidate sessions on role change).

**2. Session never re-checks `users.status` — rejected/disabled users keep access 24h**
- `app/auth/middleware.py:28-58` — no `users.status` lookup anywhere in the middleware.
  Status is only checked at login time (`app/auth/routes.py:162-167`).
- Fix: check `status == 'active'` per request (short-TTL cache), reject otherwise.

**3. Co-owners (role=owner) denied document access**
- `app/web/routes.py:77` — `_resolve_doc_owner` does `if m["role"] != "member": continue`,
  skipping co-owners. UI allows creating co-owners; backend then denies them doc
  view/download/delete. Inconsistent authorization model.
- Fix: accept both `member` and `owner` roles.

**4. `calc` tool: unbounded exponentiation → DoS / event-loop hang**
- `app/agent/tools.py:50,54-80` — `_SAFE_OPS` whitelists `ast.Pow` with no cap.
  `calc("9**9**9")` (7 chars, under the 200-char limit) evaluates `9**387420489` —
  a ~1.5 GB integer, minutes of CPU, likely OOM. Runs synchronously on the event loop.
- Fix: remove `ast.Pow` or cap exponent magnitude (e.g. reject `**` where either
  operand > 1000); add AST depth limit.

### HIGH — Reliability

**5. Worker dies permanently on transient DB error (no retry)**
- `app/queue/worker.py:51,79-95` — `claim_next_job` exceptions propagate out of
  `run_once` → out of `run_forever`'s while loop → worker thread terminates. No
  supervisor restarts it. One SQLite hiccup kills enrichment permanently.
- Fix: wrap `run_once` body in try/except with log + backoff.

**6. Job abandoned on timeout never marked failed — stuck in `processing` forever**
- `app/queue/worker.py:66-70` — `asyncio.TimeoutError` is caught and discarded with
  only a log warning. `complete_job` never runs. After `MAX_JOB_ATTEMPTS=3` the job
  is permanently unclaimable and sits in `processing` with no terminal status.
- Fix: in the `except TimeoutError` block, call `complete_job(conn, job_id, error="timeout")`
  and `update_doc_status(uconn, doc_id, "failed")`.

**7. `delete_collection` orphans files on partial failure**
- `app/web/routes.py:226-252` — DB rows deleted first, then `shutil.rmtree` per doc.
  If rmtree raises or the process dies between, files are orphaned with no DB trail.
  (Design tradeoff is documented, but there's no cleanup queue.)
- Fix: per-doc try/except logging orphans to a cleanup queue; startup sweep retries.

### MEDIUM

**8. `_get_client` TOCTOU race — concurrent reset closes client mid-use**
- `app/gateway/ollama.py:18-23` — fast path reads `self._client` without the lock;
  `_reset_client` sets `_client = None` then `aclose()`s. A request that grabbed the
  old reference fails on a closed client.
- Fix: swap under lock / generation counter; close old client after swap.

**9. `call()` resets the shared client on ANY exception**
- `app/gateway/ollama.py:55-62` — `except Exception: await self._reset_client()` fires
  on HTTP 4xx/5xx and JSON decode errors too. One bad request (e.g. 429) tears down
  the shared client, disrupting all concurrent requests. `stream()` is inconsistent
  (only resets on ConnectError/RemoteProtocolError).
- Fix: reset only on connection-level errors; align `call()` and `stream()`.

**10. Synchronous tool execution blocks the FastAPI event loop**
- `app/agent/loop.py:477` — `self.toolbox.execute(name, args)` runs sync inside the
  async `run_stream` generator. `grep` (rglob + full-file reads + regex) can take
  ~500ms+; during that time ALL concurrent requests on the worker are blocked.
- Fix: `await asyncio.to_thread(self.toolbox.execute, name, args)`.

**11. `stop()` stops heartbeat while job mid-flight → lease expires → duplicate processing**
- `app/queue/worker.py:32` — heartbeat loop exits on stop event while `run_forever`
  waits for the in-flight job (up to 4h). Lease (300s) expires; in multi-worker
  deployments another worker reclaims and reprocesses.
- Fix: keep heartbeating until the in-flight job completes.

**12. Non-dict tool args crash `run_stream` uncaught**
- `app/agent/loop.py:389-392` — `args = json.loads(args_str) if isinstance(args_str, str) else args_str`;
  a list/int args value passes through, then `args.items()` raises `AttributeError`
  uncaught, aborting the SSE stream. Model output is untrusted input.
- Fix: `if not isinstance(args, dict): args = {}`.

**13. Agent tools not collection-scoped (read_file/ls/table_extract)**
- `app/agent/tools.py:197-200,298-300,270` — these tools enforce only the owner-level
  directory boundary (`validate_user_path`), not the current collection's doc set.
  A shared-collection member can ask the agent to read files from OTHER collections
  of the same owner. (`grep` IS collection-scoped via SQL; but `grep` with an explicit
  `path` arg falls back to owner-level only.)
- Fix: scope filesystem tools to the collection's doc_ids.

**14. Grep citations never extracted**
- `app/agent/loop.py:90-150` — grep results are stored as JSON
  (`json.dumps(self.grep(...))`), but `_extract_cites_from_history` parses grep content
  as `path:line:text` text lines. The JSON never matches → grep-based citations are
  silently dropped. Only fts_search/read_file produce citations.
- Fix: `json.loads` the grep content and iterate result dicts.

## Consensus: FALSE-POSITIVES (rejected)

- **Dice DoS** (`roll(1000000,1000000)`) — capped at `MAX_DICE=100`/`MAX_SIDES=1000`,
  raises ValueError before rolling. (3/3 rejected)
- **`<img src="data:">` XSS via markdown** — `nh3.clean` strips `src` (verified against
  nh3 0.3.6); `<img>` is not a script-execution context. (2/3 rejected; claude rates
  it MEDIUM defense-in-depth only)
- **`data-msg` collection-name XSS** — Jinja autoescape prevents attribute breakout;
  `confirm()` displays text, never evaluates JS. (2/3 rejected)
- **`add_turn` `in_transaction` guard "never fires"** — true that it's dead code, but
  both callers (`history.py:22-23,38`) already hold `BEGIN IMMEDIATE`; no race exists.
  Cosmetic cleanup only.
- **Path-existence oracle in `doc_search_path`** — the fallback only probes roots the
  user already has access to; leaks nothing they couldn't see by browsing. (1/3 rejected,
  2/3 rate it LOW)

## Recommended fix order

1. **#4 calc Pow DoS** — 1-line bound, blocks the whole server (HIGH, trivial fix)
2. **#5 + #6 worker resilience** — try/except + timeout→failed marking (HIGH, enrichment
   currently dies silently)
3. **#1 + #2 auth staleness** — DB-verify admin + status per request (HIGH, 24h windows)
4. **#3 co-owner access** — one-line role check fix (HIGH, broken feature)
5. **#8 + #9 gateway client lifecycle** — lock swap + narrow reset (MEDIUM, affects all
   concurrent requests)
6. **#10 to_thread tool execution** — event-loop blocking (MEDIUM)
7. **#12 non-dict args guard** — one-line defensive fix (MEDIUM)
8. **#13 tool collection scoping** — real cross-collection read gap (MEDIUM)
9. **#14 grep citations** — citation quality (LOW)
10. **#7 delete_collection orphan queue** — data-loss path (HIGH impact, LOW likelihood)

## Positive controls verified

- All SQL parameterized (no injection found)
- `validate_user_path` symlink-safe path checks on file-serving routes
- Jinja autoescape global; only `Markup()` use is `nh3.clean`-sanitized markdown
- CSRF synchronizer token + origin middleware + Argon2id + dummy-hash timing defense
- Rate limiting on login/register (not silently disableable)
- HttpOnly/SameSite=Lax/Secure cookies; per-request CSP nonces
- Worker/web gateway isolation (separate client instances)
- Agent loop memory bounded (max_iterations=15, step_log=8, file_cache bounded)
- `_reset_client` deadlock correctly avoided (lock not held during aclose, 5s wait_for)
- `fts_search` match_mode index math correct for all cascade shapes
- `_PATHOLOGICAL` regex + per-line 0.25s timeout guards grep backtracking
